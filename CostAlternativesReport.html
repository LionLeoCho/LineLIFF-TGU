落差的兩個可能解釋

  • 大量請求超過 272K tokens。Copilot 對 OpenAI 模型在 >272K 級距約加倍收費（Astra 20 / 2.00 / 25 / 75）。若多數請求落在高級距，重算金額約 $20,450，與提供總額幾乎吻合。長對話反覆讀取上下文正是本期 96.5% 快取讀取的來源，此解釋可能性較高。
  • $20,000 含本機紀錄以外的用量。例如團隊其他成員、Copilot code review（每次 13 個 premium request）、雲端代理等未納入 session 紀錄的項目。

對比較的影響：Claude 對 4.6 以後的模型不收長上下文加價（1M context 皆為標準價）；因此本期若真的多為長上下文請求，改用 Claude 的實際節省幅度會比下表保守值更大。OpenAI 牌價同樣有 >272K 加倍級距。

驗證方式：向 GitHub 帳單後台調出九月依模型、依級距的實際 token 計費明細，與本表對帳。

地端能承接的只有輕量工作，而這類工作在雲端輕量模型上每月只要 $30～$320，低於地端的攤提與人力。選擇地端的正當理由是資料不出境、合規稽核（例如 ISO 27001 範圍內的原始碼不外送），而不是省錢。若有這類需求，建議以 1～2 台做「敏感資料／輕量工作」的小範圍試點，不要以取代全部用量為目標。

五、結論與建議

以同等級模型、相同用量換算，Claude 方案月費約 $3,400～4,600，為現況的 17%～23%；若同時落實上下文控管，可到 $2,800 左右。

Codex／Cursor 若沿用 GPT-6 Astra 不會比 Copilot 便宜；Mac mini 地端只在合規需求下有意義。

1. 先對帳，再決定換不換

向 GitHub 調出九月依模型、依級距（≤272K／>272K）的實際 token 計費明細。若證實多數費用來自 >272K 級距，則改用無長上下文加價的 Claude 效益最大；若 $20,000 含其他成員用量，本報告各方案金額需等比放大。

驗證方式：GitHub 帳單明細與第一節表格的重算金額對得起來。

2. 最大單一節省來源：離開 GPT-6 Astra

Astra 快取讀取每百萬 $1.00，Opus 5.5／Sonnet 5.5 為 $0.20，GPT-6.1 Sol 為 $0.10。本期 26.8% 的 token 用在 Astra，卻佔 45.5% 的成本。即使不換工具，先把 Astra 限制在規格衝突判斷、跨模組根因分析與高風險變更審查，其餘改中階模型，就能壓到 $6,200 左右（≤272K 口徑）。

3. 快取讀取占成本 52%～71%，上下文控管比換模型更根本

延續原報告「減少長對話反覆讀取上下文」的方向：不同 Issue 分開處理、以短交接摘要傳遞決策、大量 log 留在檔案只讀必要範圍。快取讀取每減少 10%，在 Claude 三級分派下約省 $215／月，在保留 Astra 的 OpenAI 分派下約省 $370／月。

驗證方式：比較同類任務每個完成項目的 token 數與成本，而非單次請求費用。

4. 建議的導入順序

  • 第一步（不換工具）：Copilot 內把 Astra 限縮至高風險工作，低風險工作改 GPT-6.1 Sol 或 Claude Sonnet 5.5，觀察一個月的返工率。
  • 第二步（小範圍試點）：一個小組改用 Claude Enterprise 或 Team Premium，以三級分派跑同類任務，記錄每完成項目的成本、正確率與返工率，與 Copilot 組對照。
  • 第三步（依數據擴大）：試點若證實品質相當、成本落在 $3,000～5,000 區間，再評估全面轉移；席位制（Team）與用量制（Enterprise）的取捨依實際人數與用量集中度決定。
  • 地端：僅在 ISO 27001 等合規需求下，以 1～2 台 Mac mini 承接敏感原始碼的輕量工作，不以取代雲端為目標。

5. 本報告尚未涵蓋

  • 企業折扣、年約價、區域處理加價（OpenAI 公告 10%）。
  • 模型更換後的品質差異與返工成本——本報告沒有同類任務的模型對照實驗。
  • Cursor on-demand 計費是否含平台加價（官方未公開）。
  • Copilot 2026-06-01 新計費（AI Credits）各方案內含額度。
  • 工具轉換的學習成本、既有 workflow／MCP／代理設定的搬遷工時。
